# PROJECT: AI-NATIVE FIELD ADDRESS GEOCODER

You are a senior ML engineer, geospatial ML researcher, backend engineer, frontend engineer, and competition strategist.

Build a complete, working prototype for the **OpenIIT Data Analytics Competition**, based on CreditNirvana Problem Statement 3:

> **Address Geocoder That Learns from Field Visits**

The objective is to build an AI-powered geocoding and location intelligence system for Indian debt-collection field operations.

The system must take messy Indian borrower addresses, historical field-visit GPS evidence, visit outcomes, GPS trails, dwell time, agent remarks, and nearby confirmed accounts, and produce:

1. Predicted latitude/longitude
2. Confidence score
3. Confidence radius in metres
4. Human-readable landmark-based directions
5. Evidence supporting the prediction
6. An indication of whether the address should be visited directly or verified first

The system must continuously improve as trustworthy field visits are added.

The project must be designed as a serious competition submission, not a toy demo.

# 4. CRITICAL DATA PRINCIPLE

Historical visit GPS is NOT guaranteed ground truth.

A successful visit GPS can represent:

* borrower home
* borrower shop
* roadside meeting
* nearby meeting point
* inaccurate GPS
* agent-selected meeting point

Failed visit GPS represents where the agent searched, not necessarily the actual address.

Therefore:

**NEVER treat every GPS point as an exact label.**

Implement an explicit evidence reliability mechanism.

# 12. FAKE / LOW-INTEGRITY VISIT DETECTION

Implement a separate module:

```text
backend/ml/visit_integrity.py
```

Detect suspicious evidence such as:

* repeated identical coordinates across many unrelated accounts
* agent home-like location
* unusually short visits
* impossible movement speed
* GPS jumps
* repeated tea-shop/common-point coordinates
* suspiciously identical trajectories
* implausible visit timing
* poor GPS accuracy
* abnormal agent-specific patterns

Do NOT automatically delete suspicious visits.

Instead assign:

```text
integrity_score
```

and reduce their influence.

Maintain auditability.

# 13. AGENT BIAS CONTROL

No single agent should be able to move the predicted location significantly.

Implement safeguards such as:

* cap contribution from one agent
* aggregate evidence across agents
* require multiple independent observations for high confidence
* downweight anomalous agent behaviour
* avoid overfitting to one agent's GPS pattern

A single GPS point must never dominate a prediction when contradictory evidence exists.
